# Bug 366 — Split ownership of pane lifetime → write-after-destroy + double deinit

### 366. Latent UAF masked by arena no-op frees
**File:** `src/layout.zig:50-86`, `src/layout.zig:311-316`;
call chain `destroyPane` → `Window.removePane` (window.zig:415-435) →
`layout.removePane`; then `src/server/server.zig:835-837`:
**Severity:** MEDIUM
**Status:** 🔴 OPEN

### Problem
```zig
win.removePane(self.allocator, pane);
pane.valid = false;      // write AFTER layout already destroyed the pane
pane.deinit();           // second deinit (guarded only by `deinited`)
```

Under GPA this is a use-after-free write plus double deinit. The ownership
contract ("who owns a Pane?") is ambiguous between Layout.deinitNode,
Window.removePane, and Server.destroyPane.

### Fix (proposed)
Pick one owner (recommend Layout stops destroying panes; removal detaches only)
or make `removePane` return the detached pane so the caller performs the single
teardown. Assert single-deinit in tests.
