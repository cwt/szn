# Bug 376 — Request/response packets dropped for behind clients

### 376. Render frames are droppable; replies are not
**File:** `src/server/server.zig:2538-2544` (`appendClientOut`),
`src/server/server.zig:2265-2271` (`queueToClient`)
**Severity:** MEDIUM
**Status:** 🔴 OPEN

### Problem
The behind-client backpressure path (bug #303 lineage) drops *all* output,
including `.command` responses. The issuing client then waits indefinitely on
`recvPacket`. Distinguishing droppable render data from request/response
traffic is required.

### Fix (proposed)
Queue command/err/ready/exit replies onto a separate non-droppable side channel
(or force a synchronous flush before responding). Test: mark a client behind,
issue a command, assert the reply still arrives after the backlog clears.
