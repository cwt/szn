# Bug 579 — `client-log-file` reassignment loses the old value on OOM

### 579. Free-before-dupe plus `catch ""` discards a working configuration on allocation failure

**Severity:** LOW  
**Status:** ✅ RESOLVED — the replacement path is duped before the old one is freed; OOM propagates and leaves the previous path configured. Empty values map to static `""`.  
**Files:** [`src/server/server.zig:276`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L276), [`:355`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L355), [`:3983-3989`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3983-L3989)  
**Related:** [Bug #557](./557.md) (config error handling), [Bug #573](./573.md), [Bug Index](./index.md)

## Symptom

```zig
// server.zig:276
client_log_file: []const u8 = "",

// server.zig:3983-3989
if (std.mem.eql(u8, s.option, "client-log-file")) {
    if (s.value == .string) {
        if (self.client_log_file.len > 0) self.allocator.free(self.client_log_file);
        self.client_log_file = self.allocator.dupe(u8, s.value.string) catch "";
    }
    continue;
}
```

If `allocator.dupe` fails, the previous heap-allocated path has already been freed and the field is set to the static empty string, so client logging is silently disabled even though the config still specifies a path. A zero-length value is also dupe'd into an allocation that the `len > 0` guard in `Server.deinit` (`:355`) will never free[^src-1].

## Cause

Ordering: free happens before the replacement is successfully allocated, and the failure fallback is a static literal. The audit report's stronger claims (use-after-free via aliasing, invalid free of `.rodata`) were **not** confirmed: `s.value.string` is independently owned by `ParseResult`, and the `len > 0` guard correctly avoids freeing the default `""`. Only the OOM path and zero-length allocation remain valid defects.

## Fix

Dupe before freeing and preserve the old slice on failure:

```zig
const new_path: ?[]u8 = if (s.value.string.len > 0)
    try self.allocator.dupe(u8, s.value.string)
else
    null;
if (self.client_log_file.len > 0) self.allocator.free(self.client_log_file);
self.client_log_file = if (new_path) |p| p else "";
```

Passing `try` propagates `OutOfMemory` instead of silently accepting a broken config. A longer-term clean-up is to change the field to `?[]u8 = null` so ownership is unambiguous at `:355` and `:3016-3021`.

## Verification status

Confirmed against live source: the handler freed the old path before duping and fell back to static `""` on failure. Reordered to dupe-before-free with `try`, and made empty values map to `""` without allocating. A new FailingAllocator test asserts the old path survives an OOM. `zig build test` passes on 0.16.0 and 0.17.x (1137 tests).
