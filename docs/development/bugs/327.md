# Bug 327 — Copy mode single-line backward selection yank failure

### 327. Copy mode single-line backward selection yank failure
**File:** `src/mode_copy.zig:322-332`
**Severity:** MEDIUM
**Status:** ✅ FIXED

In `yankSelection`, `start_is_top` evaluated to `true` on single-line selections (`sy_i64 == ey_i64`), causing `sx = start_x` and `ex = end_x`. For backward selections (`start_x > end_x`), `sx > ex` caused the byte copying loop to exit immediately without yanking text.

### Root Cause
Improper boundary assignment when `sy == ey`.

### Fix
Set `sx = @min(start_x, end_x)` and `ex = @max(start_x, end_x)` when `sy_i64 == ey_i64`.

Copying text by selecting backward on a single line yields empty string output.
