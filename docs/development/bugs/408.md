# Bug 408 — Prompt-path kill-session never stops the server when the last session dies (the IPC path does)

### 408. Prompt-path kill-session never stops the server when the last session dies (the IPC path does)
**Severity:** MEDIUM
**Status:** 🔴 OPEN

The IPC `.command` branch checks after dispatch:

```zig
if (self.sessions.items.len == 0) {
    std.log.info("no sessions left, stopping server loop", .{});
    self.loop.running = false;
```

The interactive-prompt path (`processInput` → `dispatch.dispatchCommand` at :1493, :1499-1501) has **no** equivalent. `prefix : kill-session` with the last session leaves `running = true`: `main.zig`'s `while (server.loop.running)` spins on the listener, the attached client shows a dead screen, and the server only dies when the client closes.

**Fix:** hoist the empty-session check into one post-dispatch helper used by both paths (or evaluate it once per `run()` iteration).
