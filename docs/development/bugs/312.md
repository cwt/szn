# Bug 312 — Use-after-free in Server.processInput when action destroys active pane or session

### 312. Use-after-free in Server.processInput when action destroys active pane or session
**File:** `src/server/server.zig:1709-1835`
**Severity:** CRITICAL
**Status:** OPEN

In `Server.processInput`, pointers for `session`, `window`, and `pane` are captured at the top of the function. The function then iterates byte-by-byte through the input buffer.

If an input sequence triggers a key binding action (such as `kill-pane` or `kill-session`), `self.executeAction(action)` executes the command and deallocates the target pane or session. However, the byte processing loop continues to reference the now-dangling `pane` pointer in subsequent iterations and in trailing `pane.writeInput(self.esc_buf.items)` calls.

### Root Cause
Static pointer resolution prior to byte-by-byte processing without re-validating pane/session existence after command execution dispatch.

### Impact
Server memory corruption, undefined behavior, or crash when input sequences destroy active panes or sessions.
