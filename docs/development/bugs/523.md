# Bug 523 — DECOM (origin mode) is implemented but never enabled

### 523. `CSI ?6h` is ignored, making the origin-mode code paths unreachable
**Severity:** MEDIUM
**Status:** ⬜ OPEN (unverified — identified by static analysis)
**Files:** [`src/input.zig:929-949`](https://github.com/cwt/szn/blob/main/src/input.zig#L929-L949), [`src/screen.zig:1076`](https://github.com/cwt/szn/blob/main/src/screen.zig#L1076), [`src/screen.zig:1143`](https://github.com/cwt/szn/blob/main/src/screen.zig#L1143)

## Problem

```zig
// src/input.zig:929-949 (abridged)
fn dispatchDecset(self: *InputParser, enable: bool) Error!void {
    while (i < self.param_count) : (i += 1) {
        switch (self.params[i]) {
            1 => self.screen.mode.keypad = enable,
            7 => self.screen.mode.line_wrap = enable,
            12 => {}, // cursor blink — not implemented
            25 => self.screen.mode.cursor = enable,
            1000 => self.screen.mode.mouse_standard = enable,
            ...
            else => {},
        }
    }
}
```

Mode **6** (DECOM) is absent. `Screen.setOriginMode` exists and is tested
(`screen.zig:2278,2352,2362`; `input.zig:1889`) but has no production caller, so
`mode.origin` can never become true in a running server.

Everything that branches on `mode.origin` is therefore dead — cursor addressing
(`screen.zig:1076,1086,1134,1143`), scroll behaviour (`:1508`) — and an
application that emits `CSI ?6h` silently gets absolute rather than
region-relative addressing. `CSI ?6$p` (DECRQM) also reports the mode as
unrecognised (`input.zig:911-914`).

This is an unimplemented wire-up rather than a wrong computation: the feature is
fully implemented and tested, only the parser arm is missing.

## Proposed Fix

```zig
6 => self.screen.setOriginMode(enable),
```

plus a `6 =>` entry in the non-private DECRQM status table so
`CSI ?6$p` reports the true state. Wiring this also activates the latent
overflow in bug #525, so fix that at the same time.
