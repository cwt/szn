# Bug 568 — Global cell-size wait timer shared across panes

### 568. `cell_size_pending_since` belongs to `Server`, not to the pane that owns the buffered sixel

**Severity:** HIGH  
**Status:** ✅ RESOLVED — the wait timestamp is now per-pane (`SixelWaitEntry.pending_since` in `Server.sixel_wait_panes`); an unrelated pane's PTY read can no longer reset another pane's timeout.  
**Files:** [`src/server/server.zig:252`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L252), [`:995-1014`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L995-L1014), [`:3490-3513`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3490-L3513)  
**Related:** [Bug #401](./401.md) (same dirty/timer class), [Bug #479](./479.md), [Bug Index](./index.md)

## Symptom

With two panes buffering a sixel while waiting for a cell-size reply:

- `tickSixelWait` (:3490-3513) reads one shared timestamp for every `*Pane` in `self.sixel_wait_panes` (:300), so the second pane measures its timeout from the *first* pane's start.
- When any pane resolves and is removed, `:3511-3513` resets the timestamp to `0` for all remaining panes, restarting their wait.
- Worse, `handlePtyEvent` at `:1014` executes `self.cell_size_pending_since = 0;` unconditionally for **every** pane read that does not have `pending_sixel`. Any other pane producing output continuously resets the timer, so the waiting pane never reaches `cell_size_wait_ms`, never flushes its sixel, and keeps POLL.IN removed (:3501) — its post-sixel shell output is never delivered.

## Cause

```zig
// server.zig:252
cell_size_pending_since: i64 = 0,

// server.zig:999-1008 — one timestamp for whichever pane is currently handled
if (self.cell_size_pending_since == 0) {
    self.cell_size_pending_since = currentMillis();
}
if (now - self.cell_size_pending_since > cell_size_wait_ms) {
    pane.screen.flushPendingSixel();
    self.cell_size_pending_since = 0;
}
// server.zig:1014 — resets even for an unrelated pane
self.cell_size_pending_since = 0;
```

```zig
// server.zig:3491-3513 — same single timestamp applied to every waiting pane
const p = self.sixel_wait_panes.items[i];
if (self.cell_size_pending_since == 0) self.cell_size_pending_since = now;
if (now - self.cell_size_pending_since > cell_size_wait_ms) {
    p.screen.flushPendingSixel();
    self.cell_size_pending_since = 0;
}
...
if (self.cell_size_pending_since != 0) self.cell_size_pending_since = 0;
```

`sixel_wait_panes` stores bare `*Pane` pointers, so there is nowhere to keep a per-pane start time[^src-1].

## Fix

Store the start time with the waiting pane — either add `cell_size_pending_since: i64 = 0` and `in_sixel_wait: bool = false` to `Pane`, or change `sixel_wait_panes` to `ArrayListUnmanaged(struct { pane: *Pane, pending_since: i64 })`. Expire each pane independently against its own timestamp. Remove or narrow the unconditional reset at `:1014` so it only clears state for the pane whose sixel actually resolved.

## Verification status

Found by source-level validation of an external 2026-11-26 audit report (since removed) against live source. Confirmed against `src/server/server.zig`: `handlePtyEvent` reset the shared `cell_size_pending_since` for every pane read and `tickSixelWait` applied it to all wait entries. Fixed by storing `pending_since` with each `SixelWaitEntry`; the new regression test `"sixel wait timeout is tracked per pane, not shared — bug #568"` drives two concurrent waiters, expires only one, and checks the other's timestamp survives. `zig build test` passes on 0.16.0 and 0.17.0 (1127 tests on each).
