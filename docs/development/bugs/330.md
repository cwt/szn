# Bug 330 — Input parser drops interrupting Escape (0x1B) control bytes

### 330. Input parser drops interrupting Escape (0x1B) control bytes
**File:** `src/input.zig:303`
**Severity:** MEDIUM
**Status:** OPEN

When state handlers such as `advanceCsiParam` or `advanceCsiIntermediate` encounter unexpected characters, they call `self.toGround()` and consume the byte.

If the unexpected byte is `0x1B` (`ESC`), the opening byte of a new sequence is consumed and lost.

### Root Cause
Consuming state-interrupting control bytes on state transitions instead of re-evaluating them in `.ground` state.

### Impact
Interrupted CSI control sequences swallow subsequent valid escape sequence prefix bytes.
