# Bug 570 — Pane border `window_index` disagrees with the status line

### 570. `#{window_index}` in `pane-border-format` is `window.id`, not the window's index in the session

**Severity:** LOW  
**Status:** ⬜ OPEN  
**Files:** [`src/server/server.zig:607-617`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L607-L617), [`:3695-3701`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3695-L3701), [`src/status.zig:261-262`](https://github.com/cwt/szn/blob/main/src/status.zig#L261-L262), [`:328-331`](https://github.com/cwt/szn/blob/main/src/status.zig#L328-L331)  
**Related:** [Bug #213](./213.md) (introduced `window_index` from `window.id`), [Bug #248](./248.md), [Bug Index](./index.md)

## Symptom

The border context is built as:

```zig
// server.zig:3695-3701
const win_idx_str = std.fmt.bufPrint(&win_idx_buf, "{d}", .{window.id}) catch "0";
ctx.set("window_index", win_idx_str);
```

The status line uses a different definition:

```zig
// server.zig:607-617
const base_index: i64 = session.options.asNumber("base-index") orelse 0;
for (session.windows.items, 0..) |win, i| {
    .index = @intCast(base_index + @as(i64, @intCast(i))),
...
// status.zig:328-331 — uses w.index
```

`Window.id` is allocated from `Session.next_win_id` (starting at 1) and is never reused, whereas `WindowInfo.index` is the slot position plus `base-index`. With `base-index 5`, or after killing window 0 and creating a new one, the border label `#I` and the status-line `#I` show different numbers for the same window[^src-1][^src-2].

## Cause

Bug #213 added the missing `window_index` key by using `window.id` as a convenient monotonic stand-in. That fixed the empty-border symptom but did not match tmux's index semantics or the server's own `buildStatusLine` calculation.

## Fix

Compute the pane's window index from its position in `session.windows.items` plus `base-index`, exactly as `buildStatusLine` does, and share one helper so both render paths agree. Resolve the owning window via `pb.pane.window` rather than assuming the active window.

## Verification status

Found by source-level validation of the audit report against live source. `zig build test` passes; no test compares border `#{window_index}` against status `#I` with a non-zero `base-index` or after a window kill.
