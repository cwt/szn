# Bug 543 — Orphan `"default"` session and background shell leaked on `szn new-session -s <name>`

### 543. `runServerDaemon` pre-creates `"default"` and spawns an extra shell even when the startup command was `new-session`
**Severity:** HIGH  
**Status:** ⬜ OPEN  
**Files:** [`src/main.zig:302-318`](https://github.com/cwt/szn/blob/main/src/main.zig#L302-L318), [`src/main.zig:480-534`](https://github.com/cwt/szn/blob/main/src/main.zig#L480-L534), [`src/cmd/cmd.zig:51-74`](https://github.com/cwt/szn/blob/main/src/cmd/cmd.zig#L51-L74)

## Problem

When no server is running and the user invokes `szn new-session -s work` (or `szn new -s work`):

1. `main.zig:302-318` auto-starts the daemon via `forkAndStartServer`, which runs `runServerDaemon`.
2. `runServerDaemon` (`src/main.zig:480`) unconditionally creates a session named `"default"` (`initial_session_id = 0`) with an unspawned pane (`pty == null`).
3. `runServerDaemon` then runs 16 event-loop ticks (`src/main.zig:511-513`) so initial client commands can be processed before spawning the default shell.
4. During those 16 ticks, the parent process connects and sends `new-session -s work`. `cmdNewSession` (`src/cmd/cmd.zig:51-74`) creates a **second** session named `"work"` (`id == 1`), calls `server.setupPane(session, pane)` (spawning a shell in `"work"`), and swaps `"work"` to `server.sessions.items[0]` while `"default"` moves to `server.sessions.items[1]`.
5. At `src/main.zig:518-534`, `runServerDaemon` searches `server.sessions.items` for `s.id == initial_session_id` (`0`), finds `"default"` at `items[1]`, sees `pane.pty == null`, and spawns a **second** login shell inside `"default"`.

As a result, every cold start via `szn new-session` leaks an unwanted `"default"` session and a live background shell process.

## Proposed Fix

In `runServerDaemon` (`src/main.zig:518-534`), if another session was created and made active during the startup ticks while the pre-created `"default"` session (`initial_session_id`) still has an unspawned initial pane (`windows.items.len == 1 and panes.items.len == 1 and pane.pty == null`), destroy the unused `"default"` session instead of spawning a shell in it (or have `cmdNewSession` reuse the unspawned initial `"default"` session by renaming and configuring it when `pty == null`).
