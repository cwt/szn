# Bug 344 — `main()` returns `void` instead of `!void` (Zig 0.16 rule #1)

### 344. `main` signature non-compliant with Zig 0.16
**File:** `src/main.zig:220`
**Severity:** LOW
**Status:** 🔓 OPEN

Zig 0.16 rule #1 states: *"`main` takes `init`"* and the canonical form is:

```zig
pub fn main(init: std.process.Init) !void {
```

The current signature is:
```zig
pub fn main(init: std.process.Init) void {
```

The error handling is done inside `mainInner` via an explicit `catch |err|` block, which is functionally correct but inconsistent with the 0.16 convention. The compiler and tooling expect `!void` so that unhandled panics or unexpected errors bubble up through the runtime rather than being silently swallowed by the `void` return type.

**Fix:** Change the signature to:
```zig
pub fn main(init: std.process.Init) !void {
    return mainInner(init);
}
```
And let `mainInner` propagate errors naturally (it already returns `Error!void`). Remove the explicit `catch |err|` wrapper from `main` and let the error path use `std.log.err` / `std.debug.print` in a proper error handler if needed, or simply return the error and let the runtime print it.

Note: this is a low-severity issue because the current code works correctly — the `catch` block inside `main` handles all errors explicitly. The fix is a signature change only.
