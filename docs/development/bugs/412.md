# Bug 412 — Peer-controlled resize

### 412. Peer-controlled resize: unbounded u32 dimensions, session.resize partial failure silently desyncs geometry, status row subtracted even when status is off
**Severity:** MEDIUM
**Status:** 🔴 OPEN

`.resize` reads raw u32 off the wire and only *lower*-bounds them (`@max(new_w, 2)`) — a buggy/malicious client can claim 4 294 967 295 × the same. `recalculateMinimumSize` then calls `s.resize(self.display_sx, self.display_sy - 1)` (:2610): `Session.resize` commits `self.width/height` *first* and then resizes windows one-by-one, swallowing each failure (`catch |err| warn`) — a mid-list OOM leaves session dims, window dims, and grid dims permanently inconsistent with no retry. And `- 1` subtracts the status row unconditionally even when `status` is off, disagreeing with the render side (which derives content height per client).

**Fix:** clamp to a sane maximum (e.g. 4096×4096); make resize transactional (validate/pre-size everything, commit only when all succeed); subtract the status row only when enabled.
