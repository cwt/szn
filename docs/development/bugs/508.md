# Bug 508 — README.md test count is stale

### 508. Public test-count claim is three behind the actual suite
**Severity:** LOW (correctness)  
**Status:** ✅ FIXED  
**Files:** [`README.md:133`](https://github.com/cwt/szn/blob/main/README.md#L133), [`docs/development/progress.md:43`](https://github.com/cwt/szn/blob/main/docs/development/progress.md#L43)

## Problem

```markdown
<!-- README.md:133 -->
- **1,032 unit and integration tests passing.**
```

The actual suite, verified 2026-09-27 with `zig build test --summary all` on
Zig 0.16.0:

```
+- run test 1034 pass, 1 skip (1035 total)
```

`docs/development/progress.md:43` was corrected to `1,034 / 1,035` on
2026-09-27, but the README was not. Because the README is the project's front
door, its claim is the more visible of the two, and the two now disagree.

The drift is explainable: bugs #502 and #504 added three tests to
`src/thai.zig` (two for the compound-vowel cluster case, one for concurrent
`libthai` access), taking the count from 1,032 to 1,035.

The wording is also imprecise. "1,032 tests passing" conflated total with
passing; the suite now has 1,035 tests of which 1,034 pass and 1 is skipped, so
"1,032 tests passing" was already understating the suite by the skipped test
even when the total was correct.

## Proposed Fix

```diff
-- **1,032 unit and integration tests passing.**
+- **1,035 unit and integration tests (1,034 passing, 1 skipped).**
```

To prevent recurrence, either drop the hardcoded count in favour of a pointer
to `docs/development/progress.md`, which is the designated status tracker per
AGENTS.md, or add the count to a CI check that fails when the README and the
suite disagree.

## Resolution

Fixed, with the count taken after the other four bugs in this batch had added
their tests, so it is not stale on arrival.

* `README.md:133` now reads "**1,041 unit and integration tests (1,040 passing,
  1 skipped).**" — separating total from passing, which the old wording
  conflated.
* `docs/development/progress.md` was updated to the same figures and now records
  the `-Doptimize=ReleaseFast` verification mode.

The six new tests in this batch (#506 x5, #510 x1) account for the increase from
1,035 to 1,041.
