# Bug 340 — `std.StringHashMap` and `std.AutoHashMap` use managed (pre-0.16) API

### 340. Managed hash-map types used instead of unmanaged 0.16 equivalents
**Files:** `src/format.zig:28,31`, `src/server/server.zig:133,275`
**Severity:** HIGH
**Status:** 🔓 OPEN

Zig 0.16 removed the managed `.init(allocator)` constructor pattern for containers. All lists and maps must use the `*Unmanaged` variants with `.empty` init, and every mutation method must receive the allocator explicitly.

**`src/format.zig` — `Context` struct**

```zig
// WRONG (managed 0.15 style):
map: std.StringHashMap([]const u8),
// ...
return .{ .map = std.StringHashMap([]const u8).init(allocator) };
```

Should be:
```zig
map: std.StringHashMapUnmanaged([]const u8) = .empty,
// init:
return .{ .map = .empty };
// deinit:
var it = self.map.iterator();
while (it.next()) |entry| {
    self.map.allocator.free(entry.key_ptr.*);
    self.map.allocator.free(entry.value_ptr.*);
}
self.map.deinit(allocator);
```

**`src/server/server.zig` — `Server` struct**

```zig
// WRONG (managed):
.client_readers = std.AutoHashMap(i32, *MessageReader).init(allocator),
```

Should be:
```zig
.client_readers = std.AutoHashMapUnmanaged(i32, *MessageReader){},
// or with explicit field init:
.client_readers = .empty,
```

And every `put`/`get`/`remove` call must pass `allocator` explicitly:
```zig
try self.client_readers.put(allocator, fd, reader);
```

**Fix:** Replace `std.StringHashMap` → `std.StringHashMapUnmanaged`, `std.AutoHashMap` → `std.AutoHashMapUnmanaged`, `.init(allocator)` → `.empty`, and thread `gpa`/`allocator` into every container method call.
