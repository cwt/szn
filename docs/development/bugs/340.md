# Bug 340 — `std.StringHashMap` and `std.AutoHashMap` use managed (pre-0.16) API

### 340. Managed hash-map types — FALSE POSITIVE
**Files:** N/A
**Severity:** HIGH (downgraded)
**Status:** ❌ FALSE POSITIVE

Initial analysis incorrectly flagged `std.StringHashMap` and `std.AutoHashMap` as pre-0.16 managed APIs. Verification against the actual Zig 0.16 std lib (`/opt/homebrew/Cellar/zig/0.16.0_1/lib/zig/std/hash_map.zig`) confirms:

- `pub fn StringHashMap(comptime V: type) type` — line 64, still exists
- `pub fn AutoHashMap(comptime K: type, comptime V: type) type` — line 46, still exists
- Both have `.init(allocator)` (line 170) and `.deinit(self: *Self)` (line 211)

The managed variants are still the recommended default for most use cases. The unmanaged `*Unmanaged` variants exist as an alternative but are not required.

**No code changes needed.**
