# Bug 389 — IPC / tty hygiene cluster

### 389. Four small IPC/terminal-setup defects
**Severity:** LOW
**Status:** 🔴 OPEN

| # | Site | Finding |
|---|------|---------|
| a | connect.zig:22 | Client socket created without SOCK_CLOEXEC — unlike server/pty fds — so it leaks into anything the client spawns. |
| b | message_reader.zig:93-95 | `packetType` does `@enumFromInt` on a closed enum with a wire-controlled byte → checked panic if ever called. Currently unused in production (server uses fromByte); delete or return `?MessageType`. |
| c | protocol.zig:101-114 | `Packet.make` clamps declared length to maxInt(u32) but keeps the full data slice; serialize would copy more body than the header declares. Unreachable today; should reject instead of fabricating. |
| d | raw.zig:36-44 | `setRaw` zeroes iflag/lflag/oflag but never forces CS8 / clears PARENB (cfmakeraw parity rules) — 7-bit or parity terminals mangle UTF-8 input. `deinit` restores with TCSA.FLUSH, discarding pending output. |
