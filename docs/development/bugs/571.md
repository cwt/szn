# Bug 571 — Cached pane borders survive renames

### 571. `#{pane_title}`, `#{window_name}`, and `#{session_name}` remain stale until the option is set again

**Severity:** MEDIUM  
**Status:** ⬜ OPEN  
**Files:** [`src/server/server.zig:3680-3683`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3680-L3683), [`:4080-4084`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L4080-L4084), [`src/window.zig:335-343`](https://github.com/cwt/szn/blob/main/src/window.zig#L335-L343), [`:456-464`](https://github.com/cwt/szn/blob/main/src/window.zig#L456-L464), [`src/session.zig:161-170`](https://github.com/cwt/szn/blob/main/src/session.zig#L161-L170)  
**Related:** [Bug #433](./433.md) (geometry invalidation), [Bug #563](./563.md) (automatic rename), [Bug Index](./index.md)

## Symptom

The render path serves a pre-expanded string on generation match:

```zig
// server.zig:3681-3683
if (pb.pane.border_format_gen == border_gen and pb.pane.border_format_cached != null) {
    pb.border_format = pb.pane.border_format_cached.?;
    continue;
}
```

`border_format_gen` is bumped only when `pane-border-format` itself is set (`server.zig:4080-4084`, also `cmd/cmd.zig`). `Window.invalidateBorderFormat()` (`window.zig:456-464`) is called on resize/add/split/remove (`:453`, `:484`, `:512`, `:536`) and on pane swap (`server.zig:1692`), but **not** on:

- `Window.setName` (`window.zig:335-343`), which only sets `name_dirty`;
- `Session.rename` (`session.zig:161-170`), which only sets `active_window_dirty`;
- automatic foreground-process rename via `applyForegroundProcessName` → `win.setName` (`server.zig:3918`);
- OSC 0/2 title updates, which flow through `windowTitleCallback` → `win.setName` (`window.zig:555-573`).

Because the border context sources `pane_title` and `window_name` from `window.name` and `session_name` from `session.name` (`server.zig:3699-3703`), a rename leaves the old title painted on every affected border indefinitely[^src-1][^src-2][^src-3].

## Cause

The invalidation added for #433 covered geometry mutations only. Name mutations were never wired to the same generation counter.

## Fix

Call `window.invalidateBorderFormat()` from `Window.setName` when `changed` is true, from `Session.rename` for all windows in the session, and wherever an OSC/foreground rename reaches those setters. Alternatively bump `session.border_format_gen` on the same events. Take care that `invalidateBorderFormat` frees with `pane.screen.grid.allocator` and is safe when a window has no panes yet (e.g. during `Window.init`).

Found by source-level validation of the audit report against live source. `zig build test` passes; no test asserts a border update after `rename-window`, OSC title change, or automatic rename.
