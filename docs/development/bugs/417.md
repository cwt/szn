# Bug 417 — Bare split-window defaults to different directions through the two dispatch paths (bind-key → vertical, CLI/prompt → horizontal)

### 417. Bare split-window defaults to different directions through the two dispatch paths (bind-key → vertical, CLI/prompt → horizontal)
**Severity:** MEDIUM
**Status:** ✅ RESOLVED

`bind-key % "split-window"` (flagless) goes through the mini parser in key_binding.zig: `return if (is_h) .split_horizontal else .split_vertical;` — default **vertical**. The same command string through the prompt/CLI enters `cmdSplitWindow`, which starts `var direction = .horizontal` and only `-v` flips it — default **horizontal**. The command table's own description ("Split the current pane horizontally (-v for vertical)") documents the CLI reading, so `bind-key ' split-window'` (default binding `%` equivalent) splits the opposite way from typing the same text. The flagless default now differs per route; the token matching is also substring-loose enough to misclassify unusual flag spellings.

**Fix:** one command→Action mapping: have key_binding hand the raw string to the cmd.zig parser instead of re-deriving direction from a mini-parse.
