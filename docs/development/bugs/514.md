# Bug 514 — U+00A0 NBSP treated as zero-width

### 514. The Latin-1 fast path's control-range upper bound includes NO-BREAK SPACE
**Severity:** MEDIUM
**Status:** ⬜ OPEN
**Files:** [`src/char_width.zig:229-231`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L229-L231)

## Problem

```zig
// src/char_width.zig:228-232
// Fast path: ASCII printable + Latin-1 Supplement
if (cp < 0x0300) {
    if (cp < 0x20 or (cp >= 0x7F and cp <= 0xA0)) return 0;
    return 1;
}
```

The upper bound should be `0x9F`: the C1 control block is `0x80..0x9F`.
`0xA0` is U+00A0 NO-BREAK SPACE, which is printable and occupies one cell. Bug
#144 removed an unreachable duplicate C1 check and left this off-by-one in
place.

The consequence is not merely a wrong width report. Width 0 marks the codepoint
as a combining mark, so `writeChar` routes it to the combining path, where
`char_width.combiningIndex(0xA0)` returns 0 (it is not in the combining table)
and the character is dropped. Text that uses NBSP — common in pasted rich text,
HTML-derived content, and some `printf` output — loses those spaces entirely.

## Proposed Fix

```zig
if (cp < 0x20 or (cp >= 0x7F and cp <= 0x9F)) return 0;
```

Add a unit test asserting `charWidth(0xA0) == 1` and that writing NBSP advances
the cursor by one column.
