# Bug 453 — reflowCursorInternal trims trailing screen rows on width change, stealing history lines into visible screen

### 453. Width resize/split drops trailing screen rows and pulls history into view
**Severity:** MEDIUM  
**Status:** Open  
**Files:** [`src/grid.zig`](../../../src/grid.zig)  

---

### Symptoms

1. When splitting a pane vertically (reducing pane width from e.g. 80 to 40 columns) in a session that has scrollback history:
2. Old lines from the scrollback buffer are unexpectedly pulled onto the top of the visible screen.
3. The active shell prompt and cursor shift downward toward the bottom of the pane by the number of empty rows that were below the prompt.

---

### Root Cause Analysis

1. **Bug #347 check is restricted to equal widths**:
   In [`src/grid.zig:871`](../../../src/grid.zig#L871):
   ```zig
   var process_limit = if (found_non_empty) last_non_empty + 1 else 0;
   if (cursor_y) |cy| {
       const cursor_logical_y = cy + hist_len;
       if (cursor_logical_y < total) {
           if (process_limit < cursor_logical_y + 1) {
               process_limit = cursor_logical_y + 1;
           }
       }
   }
   if (new_width == self.width and hist_len > 0) {
       process_limit = @max(process_limit, total);
   }
   ```
   Bug #347 resolved line shifting for copy-mode entry (`new_width == self.width`). But during a vertical pane split or terminal window resize, `new_width != self.width`.
2. **Trailing empty rows on visible screen are dropped**:
   `process_limit` only scans up to `last_non_empty + 1` (or the cursor line). If the user has a prompt at row 5 on a 24-row pane, rows 6..23 are dropped from `process_limit`.
3. **Layout reconstruction steals history rows**:
   In [`src/grid.zig:1019`](../../../src/grid.zig#L1019):
   ```zig
   const h_count = total_len - height;
   vis_list.appendSliceAssumeCapacity(new_lines.items[h_count..]);
   hist_list.appendSliceAssumeCapacity(new_lines.items[0..h_count]);
   ```
   `vis_list` must take exactly `height` (24) lines. Because 18 trailing empty rows were omitted from `new_lines`, `vis_list` takes the last 24 lines of `new_lines`, which ends up pulling 18 lines out of history into `vis_list`.

---

### Proposed Fix

1. When `hist_len > 0`, preserve visible screen height during reflow regardless of whether `new_width == self.width`, or ensure trailing blank lines up to `total` are included in `process_limit`.
2. Add regression unit tests in [`src/grid.zig`](../../../src/grid.zig) verifying that vertical pane splits (`new_width < old_width`) with active scrollback do not pull history lines onto the screen.
