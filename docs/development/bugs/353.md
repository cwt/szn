# Bug 353 — Root bindings dead; triplicated prefix machine with drift

### 353. `bind-key -n` silently non-functional; dispatcher abstraction bypassed
**File:** `src/key_binding.zig:120-134`, `src/server/server.zig:1228-1238`,
`src/server/server.zig:1424`, `src/server/server.zig:1655-1662`, `src/server/server.zig:1857`, `src/server/server.zig:2006-2025`
**Severity:** HIGH
**Status:** ✅ FIXED

### Problem
- `cmdBindKey` accepts `-n` root bindings (cmd.zig:1094), the config loader
  stores them (server.zig:3095), and `list-keys` displays them (cmd.zig:677) —
  but at runtime nothing ever looked them up.
- `KeyDispatcher.dispatch()` — which checks `root_table` — was bypassed in
  production input paths in favor of manual `prefix_table.lookup()` calls.

### Root Cause
Production input paths bypassed the `KeyDispatcher` abstraction and
consulted only `prefix_table`.

### Fix (applied)
- Added `Server.handleServerKey(self: *Server, k: Key) bool` helper in `src/server/server.zig`
  that dispatches keys through `self.dispatcher.dispatch(k)` and executes matched actions.
- Connected `root_table` checks to:
  1. The ground fast path (bypasses fast bulk write if `root_table` has a binding for the character).
  2. The parsed escape / C0 / C1 key path (`handleServerKey`).
  3. The ground single-key / prefix-cancelled path (`handleServerKey`).
  4. Copy-mode key handling (checks `prefix_seen`, then `root_table`, then prefix key, then copy-mode keys).
- **Tests:** `root key table bind-key -n dispatching — bug #353` in `src/server/server.zig` tests function keys (`F1`), control keys (`Ctrl-N`), and root bindings triggered from within copy-mode.
