# Bug 353 — Root bindings dead; triplicated prefix machine with drift

### 353. `bind-key -n` silently non-functional; dispatcher abstraction bypassed
**File:** `src/key_binding.zig:120-134`, `src/server/server.zig:1546-1586`,
`src/server/server.zig:1700-1715`, `src/server/server.zig:1858-1889`
**Severity:** HIGH
**Status:** 🔴 OPEN

### Problem
- `cmdBindKey` accepts `-n` root bindings (cmd.zig:1094), the config loader
  stores them (server.zig:3095), and `list-keys` displays them (cmd.zig:677) —
  but at runtime nothing ever looks them up.
- `KeyDispatcher.dispatch()` — which does check `root_table` — is never called
  from production code (only from tests, cmd.zig:2163).
- The three hand-rolled copies have already drifted:
  copy-mode path checks the prefix before yank handling, ground paths ignore
  root bindings entirely, and none implement number-prefixed repeats.

### Root Cause
Production input paths bypass the `KeyDispatcher` abstraction entirely and
consult only `prefix_table`; `loadDefaults` is likewise applied only to
`prefix_table` (server.zig:264).

### Fix (proposed)
Route all three paths through `dispatcher.dispatch()` (or extract one shared
`handleKey()` helper that consults both tables). Eliminates H2/H3 together and
makes future fixes single-site.
