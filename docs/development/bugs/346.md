# Bug 346 — I/O functions do not receive `io: std.Io` parameter (Zig 0.16 rule #2)

### 346. Missing `io` capability — FALSE POSITIVE
**Files:** N/A
**Severity:** MEDIUM (downgraded)
**Status:** ❌ FALSE POSITIVE

The Zig 0.16 skill doc recommends threading `io: std.Io` through I/O functions. However, this codebase uses **raw POSIX syscalls** throughout:

- `std.c.read`, `std.c.write`, `std.c.close` — for all fd I/O
- `std.posix.poll` — for event looping
- `std.posix.pipe`, `std.posix.socket`, etc. — for IPC

The only `std.Io` usage in the entire `src/` tree is a single type alias:
```zig
// src/tty/tty.zig:12
const Writer = std.Io.Writer;
```

This is a deliberate design choice for a terminal multiplexer: raw syscalls provide the precise fd control needed for PTY management, non-blocking I/O, and signal handling. The `std.Io` capability pattern is designed for higher-level applications, not low-level terminal I/O.

**No code changes needed.**
