# Bug 496 — cell_size wire message stores unvalidated u32s

### 496. No validation on the wire; applied to every pane's Screen
**Severity:** MEDIUM (one buggy client corrupts sixel math for all sessions)
**Status:** 🟠 OPEN
**Files:** [`src/server/server.zig:2610-2622`](../../../src/server/server.zig)

## Problem

```zig
.cell_size => {
    if (pkt.data.len >= 8) {
        const height_px = std.mem.readInt(u32, pkt.data[0..4], .little);
        const width_px = std.mem.readInt(u32, pkt.data[4..8], .little);
        self.cell_px_height = height_px;
        self.cell_px_width = width_px;
        ...
        self.applyCellSizeToAllScreens();
    }
},
```

Unlike `.resize` (clamped to `[2,4096]`), `cell_px_height`/`cell_px_width` accept **any** u32 — including `0xFFFFFFFF` — and push it into every pane's `Screen`. Today `updateCellSize` rejects 0 so there's no crash, and absurd values mostly produce absurd-but-bounded sixel footprints; but one buggy or malicious client permanently corrupts the geometry math for **all** sessions server-wide, with no way to recover except restarting the server or sending a corrective message.

## Proposed Fix

Validate like `.resize`: reject 0, clamp to a sane range (e.g. `[1, 1024]` px) at the wire boundary in the `.cell_size` handler, before storing server-wide.
