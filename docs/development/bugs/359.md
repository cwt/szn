# Bug 359 — Clock mode: full-grid clone per second, arena never reclaimed

### 359. Leaving clock mode on for an hour can consume gigabytes
**File:** `src/server/server.zig:2683-2697` (also the once-per-toggle clones at
server.zig:1100, cmd.zig:553-574)
**Severity:** HIGH
**Status:** 🔴 OPEN

### Problem
Clock mode re-clones the entire saved grid — including cloned scrollback
history (grid.zig:146-176 copies history too) — every second, and the
"freed" predecessor is an `ArenaAllocator.free` no-op unless it happens to be
the most recent allocation.

### Root Cause
```zig
if (sg.clone(grid_alloc)) |cloned| {
    pane.screen.grid.deinit();     // arena no-op
    pane.screen.grid = cloned;
```

All Grid memory comes from the session arena, so nothing is ever returned.
Same clone-with-noop-free pattern fires once per copy-mode/clock-mode/
choose-buffer toggle (bug #361).

### Fix (proposed)
Render the clock directly over a retained buffer instead of cloning: keep the
saved_grid as the source of truth and repaint visible cells from it without
copying history; or give Grid/saved_grid a real general-purpose allocator (or
a resettable scratch arena) for the clock path. At minimum stop including
history in the per-second clone.
