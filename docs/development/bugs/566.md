# Bug 566 — `runServerDaemon` resurrects `"default"` on fast `new-session && kill-session` and rejects cold bare `new-session`

### 566. Pre-creating `"default"` in `runServerDaemon` causes a 16 ms daemon/shell leak race, breaks cold `szn new-session -d`, and leaks daemons on invalid `new-session` arguments

**Severity:** HIGH (orphaned daemons, leaked shells, and PTY exhaustion on scripted create/destroy workloads; broken cold `szn new-session -d`)  
**Status:** ✅ RESOLVED (rev `851:6c9f48cb2fdc`)  
**Files:**
- [`src/main.zig`](https://github.com/cwt/szn/blob/main/src/main.zig#L435-L520) (`waitForInitialSession`, `runServerDaemon`, call sites at lines 266, 286, 397)
- [`src/server/server.zig`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L868-L875) (`Server.run` clean EOF handling)

**Related:** [Bug #221](./221.md), [Bug #543](./543.md), [Bug #558](./558.md), [Bug #567](./567.md), [Bug Index](./index.md)

## Symptom

1. **Orphaned daemon + shell leak on rapid create/destroy:** Running `szn new-session -d b && szn kill-session` on a cold server exited `0` for both commands, yet left a live `szn` daemon holding a resurrected `"default"` session and a running child shell (`/opt/homebrew/bin/bash`) on a PTY. Under a `hyperfine` cold-startup benchmark using isolated per-run `XDG_RUNTIME_DIR` directories, this leaked **122 `szn` daemons**, **122 `/opt/homebrew/bin/bash` shells** (~322.6 MiB RSS), and **122 / 511 PTYs** in a single 5-second run[^src-1].
2. **Cold bare `szn new-session -d` fails:** Running `szn new-session -d` (or `szn new-session -d default`) when no server was running exited with code `1` (`Error: command failed`) while still leaving a background daemon running with `"default"`[^src-1][^src-2].
3. **Invalid cold `szn new-session` leaks a daemon:** Running `szn new-session -d a b c` on a cold server returned `Error: too many arguments` (`rc=1`), yet left the newly forked daemon and a spawned `"default"` shell alive in the background[^src-1].

## Cause

The fix for [Bug #543](./543.md) kept `runServerDaemon`'s unconditional pre-creation of a `"default"` session and 16-tick (`~16 ms`) startup loop, then checked after the loop whether any *other* session still existed in `server.sessions.items`[^src-1]:

```zig
// Before (src/main.zig)
const session = try server.newSession("default", sx, sy - 1);
const default_session_id = session.id;
...
for (0..16) |_| {
    try server.run(1);
}
...
var default_session_orphaned = false;
for (server.sessions.items) |s| {
    if (s.id == default_session_id) continue;
    default_session_orphaned = true;
    break;
}
if (default_session_orphaned) {
    server.killSessionById(default_session_id);
} else if (default_pane) |p| {
    try p.spawn(allocator, &[_][]const u8{shell}, null, min_nofile);
    ...
}
```

That design had three failure modes whenever the daemon was forked for `new-session` / `new`:

* **16 ms resurrection race:** `szn new-session -d b` completed in ~2–5 ms (`server.sessions = ["b", "default"]`). When `szn kill-session` ran immediately inside the remaining 16 ms window, `cmdKillSession` ([`src/cmd/cmd.zig`](https://github.com/cwt/szn/blob/main/src/cmd/cmd.zig#L90-L105)) removed `"b"`, saw `server.sessions.items.len == 1` (`"default"`), and left `server.loop.running = true`[^src-2]. Once the 16 ticks finished, no other session existed, so `default_session_orphaned` evaluated to `false` and `runServerDaemon` spawned a fresh shell in `"default"` and ran indefinitely[^src-1].
* **Duplicate-name collision with [Bug #558](./558.md):** `cmdNewSession` defaults an omitted name to `"default"` and rejects duplicate session names ([`src/cmd/cmd.zig`](https://github.com/cwt/szn/blob/main/src/cmd/cmd.zig#L50-L55)). Because `"default"` was already pre-created before the parent's command arrived, cold `szn new-session -d` and `szn new-session -d default` always failed[^src-2].
* **Leaked daemon on command failure:** If the parent's initial `new-session` command failed parsing or validation, `server.sessions` still held the pre-created `"default"` session, so `handleClient`'s zero-session shutdown check ([`src/server/server.zig`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L2908-L2911)) never fired and `runServerDaemon` proceeded to spawn `"default"`[^src-1][^src-3].

## Fix

1. **Skip `"default"` pre-creation when forked for `new-session` / `new`** ([`src/main.zig`](https://github.com/cwt/szn/blob/main/src/main.zig#L453-L520))[^src-1]:
   * Parameterized `runServerDaemon(allocator, create_default_session: bool)`:
     * `spawnDaemonAndAttach` (bare `szn` with no arguments) passes `create_default_session = true`, creating `"default"` and spawning its shell directly with no 16 ms polling delay.
     * Both `is_new_cmd` fork paths (`!socketExists` and stale-socket `ConnectionRefused`) pass `create_default_session = false`, skipping `"default"` pre-creation entirely.
   * Installed the `SIGCHLD` handler before creating/spawning or listening, and added `errdefer server.shutdownServer()` right after `try server.listen()`.
2. **Bounded initial-session wait loop** ([`src/main.zig`](https://github.com/cwt/szn/blob/main/src/main.zig#L435-L451))[^src-1]:
   * Added `waitForInitialSession(server, 5000)` for the `create_default_session = false` path.
   * Exits immediately once `server.sessions.items.len > 0` (session created), or sets `server.loop.running = false` and shuts down cleanly if:
     * The initial command leaves 0 sessions (e.g., invalid arguments or an immediate `kill-session`, handled by [`Server.handleClient`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L2908-L2911)),
     * The initial client disconnects without creating a session, or
     * The 5 s startup deadline expires without any client connecting.
3. **Avoid error-level logging on clean client EOF** ([`src/server/server.zig`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L868-L875))[^src-3]:
   * Guarded `std.log.err("client {d} error: ...")` with `if (err != error.ConnectionClosed)` so normal CLI disconnect EOFs do not spam server logs or fail Zig's zero-error-log test runner check.
