# Bug 343 — `std.c.getenv()` used everywhere instead of `init.environ_map` (Zig 0.16 rule)

### 343. Environment variable access via C runtime instead of `init.environ_map`
**Files:** `src/main.zig:170,986,997`, `src/log.zig:41,60,86,340`, `src/socket_path.zig:30,34,38`
**Severity:** MEDIUM
**Status:** 🔓 OPEN

Zig 0.16 rule #2 states: *"I/O needs `io`"* and the environment map is passed through `init.environ_map`. The migration table explicitly says:

| Old (do not use) | New (0.16) |
|---|---|
| `std.process.getEnvVarOwned` | `init.environ_map.get("KEY")` |

**Affected call sites:**

| File | Line | Code |
|---|---|---|
| `src/main.zig` | 170 | `return std.c.getenv("SZN") != null;` |
| `src/main.zig` | 986 | `const prev = std.c.getenv("SZN");` |
| `src/main.zig` | 997 | `const prev = std.c.getenv("SZN");` |
| `src/log.zig` | 41 | `if (std.c.getenv("XDG_STATE_HOME")) |xdg_raw| {` |
| `src/log.zig` | 60 | `if (std.c.getenv("HOME")) |home| {` |
| `src/log.zig` | 86 | `if (std.c.getenv("HOME")) |home| {` |
| `src/log.zig` | 340 | `const old_xdg = std.c.getenv("XDG_STATE_HOME");` |
| `src/socket_path.zig` | 30 | `if (std.c.getenv("XDG_RUNTIME_DIR")) |xdg| {` |
| `src/socket_path.zig` | 34 | `if (std.c.getenv("TMPDIR")) |tmp| {` |
| `src/socket_path.zig` | 38 | `if (std.c.getenv("HOME")) |home| {` |

**Fix:** Thread the environment map through function signatures. For functions that are called from `main` or from contexts where `init` is available, pass `init.environ_map` (or a reference to it) as a parameter. For library-level functions like `resolveLogPath` and `resolve`, add an `env: *const std.process.EnvMap` parameter (or use a string-map lookup function). Where `std.c.getenv` is used in tests to set/clear env vars, use `std.process.putenv` / `std.process.unsetenv` or the test's local env manipulation instead.

Note: `std.c.getenv` is a C library call that reads from the C runtime's `_environ` — it is thread-unsafe and does not participate in Zig's allocator-capability model. The 0.16 `init.environ_map` is a frozen snapshot of the environment at process start, which is safer and consistent with the rest of the std API.
