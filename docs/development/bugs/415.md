# Bug 415 — Config scope/flag surface is parsed but discarded

### 415. Config scope/flag surface is parsed but discarded: set -s/-w/-g, bind -r, set-environment, if-shell are dead; combined short options misparse
**Severity:** MEDIUM
**Status:** 🔴 OPEN

`SetOpt.flags.{global,session,window,server}`, `BindKey.flags.reverse` and `SetEnv.flags.global` are populated by the parser (with passing tests) and **never consulted** by `applyDirectives`: every `set` lands in the global options table regardless of flag, `set -s server-name x` / `setw status off` get the wrong scope, and `bind -r` prefix-repeat is silently lost. Combined short options corrupt the token stream: `set -gu foo v` consumes `g`, then takes `remaining[2..]` = `"u foo v"` → option name `"u"`. `.set_environment` and `.if_shell` directives are fully parsed (`findUnescapedQuote`/`unescapeQuoted` machinery + tests) but their apply side is a `TODO` no-op — dead feature surface pretending to work.

**Fix:** dispatch by flag to server/session/window option stores; iterate grouped short-option chars; implement or delete set-environment/if-shell (and their tests).
