# Bug 569 — Dirty flags cleared after a failed `collectPaneBounds`

### 569. A transient error while collecting pane bounds drops the frame but still marks it delivered

**Severity:** MEDIUM  
**Status:** ⬜ OPEN  
**Files:** [`src/server/server.zig:3630`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3630), [`:3664-3667`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3664-L3667), [`:3805-3811`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3805-L3811)  
**Related:** [Bug #401](./401.md) (same error-path class for `renderAll`), [Bug #433](./433.md), [Bug Index](./index.md)

## Symptom

Inside the `for (self.display_clients.items) |dc|` loop:

```zig
var all_flushed = true;                                   // :3630
...
dc.bounds_buf.clearRetainingCapacity();                   // :3663
self.collectPaneBounds(window.layout.root, 0, 0, dc.sx, content_h, &dc.bounds_buf) catch |err| {
    std.log.warn("collectPaneBounds error: {any}", .{err});
    continue;                                             // :3666 — no all_flushed = false
};
```

At the end of the function:

```zig
if (all_flushed) {            // :3805 — still true for the skipped client
    self.dirty = false;
    self.status_dirty = false;
    for (window.panes.items) |p| p.dirty = false;
}
```

The affected display client receives no frame for that tick, but the server records the update as delivered. Because `render_buf` diff state only advances on a completed frame, the client stays stale until unrelated PTY output happens to mark the panes dirty again[^src-1].

## Cause

`collectPaneBounds` returns `ServerError!void` and appends into `dc.bounds_buf`; its only realistic failure is `OutOfMemory` while growing that list. The error handler mirrors the *correct* pattern used one block earlier for `flushDisplayClient` (`:3637-3641`), which does set `all_flushed = false` before `continue`, but omits it here. Bug #401 fixed the analogous omission in the `renderAll` error path; this second error path was left behind.

## Fix

Set `all_flushed = false;` immediately before the `continue` at `:3666`, matching `:3639`.

## Verification status

Found by source-level validation of the audit report against live source. `zig build test` passes; no test injects an allocation failure into `collectPaneBounds`, so the stale-frame behaviour is untested.
