# Bug 345 — `std.process.Args.Iterator` is a pre-0.16 pattern; should use `init.minimal.args.toSlice(arena)`

### 345. Old args iteration pattern
**File:** `src/main.zig:237-246`
**Severity:** MEDIUM
**Status:** 🔓 OPEN

Zig 0.16 migration table:

| Old (do not use) | New (0.16) |
|---|---|
| `std.process.argsAlloc` / `getArgsAlloc` | `try init.minimal.args.toSlice(arena)` |

**Current code:**
```zig
var args: std.ArrayList([]const u8) = .empty;
defer args.deinit(allocator);

var arg_it = try std.process.Args.Iterator.initAllocator(init.minimal.args, allocator);
defer arg_it.deinit();

while (arg_it.next()) |arg| {
    const arg_dupe = try allocator.dupe(u8, arg);
    try args.append(allocator, arg_dupe);
}
defer {
    for (args.items) |arg| {
        allocator.free(arg);
    }
}
```

**Should be:**
```zig
const arena = init.arena.allocator();
const args = try init.minimal.args.toSlice(arena);
for (args, 0..) |arg, i| {
    // use arg directly — owned by the arena, freed at process exit
    _ = i;
}
```

**Why this matters:** The current code manually duplicates every argument into the general-purpose allocator (`gpa`), then manually frees each one in a deferred block. This is unnecessary allocation churn. The arena allocator (`init.arena`) is designed for exactly this kind of short-lived data — args exist for the lifetime of the process, so the arena is the correct allocator. The manual `dupe` + `free` loop also adds ~N allocations where N = number of CLI args.

**Fix:** Replace the `args` ArrayList + manual dupe loop with `try init.minimal.args.toSlice(arena)` and iterate the slice directly. The arena is already available in `mainInner` via `init.arena.allocator()`.
