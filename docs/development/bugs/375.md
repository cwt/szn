# Bug 375 — Client-side packet length unvalidated against protocol cap

### 375. Server got this right; client didn't
**File:** `src/main.zig:872-886`
**Severity:** MEDIUM
**Status:** 🔴 OPEN

### Problem
```zig
const pkt_len = std.mem.readInt(u32, ...);
if (pkt_len < 5) {...}
if (read_buf.items.len - read_pos < pkt_len) break;   // wait forever
```

No `pkt_len <= protocol.MAX_PACKET_SIZE` check (the server's MessageReader has
one). A single flipped bit or hostile injection pins the client buffering
forever via `ensureUnusedCapacity(4096)` per POLLIN.

### Fix (proposed)
Reject `pkt_len > MAX_PACKET_SIZE` exactly like client.recvPacket does
(error.PacketTooLarge → disconnect). Test: feed a header declaring an absurd
length and expect clean failure.
