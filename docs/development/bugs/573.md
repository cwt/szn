# Bug 573 — Silent config truncation on `set-environment` OOM

### 573. `catch return` reports success and stops processing `szn.conf`

**Severity:** LOW  
**Status:** ⬜ OPEN  
**Files:** [`src/server/server.zig:4155-4169`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L4155-L4169)  
**Related:** [Bug #557](./557.md), [Bug #415](./415.md), [Bug Index](./index.md)

## Symptom

```zig
.set_environment => |e| {
    ...
    const name_z = compat.dupeZ(self.allocator, e.name) catch return;   // :4160
    defer self.allocator.free(name_z);
    if (e.value) |val| {
        const val_z = compat.dupeZ(self.allocator, val) catch return;   // :4163
        defer self.allocator.free(val_z);
        _ = c_env.setenv(name_z, val_z, 1);
    } else {
        _ = c_env.unsetenv(name_z);
    }
},
```

`applyDirectives` returns `ServerError!void`, so a bare `return` on allocation failure is **success**. Callers see a fully applied config and continue, while every directive after this `set-environment` line was skipped[^src-1].

## Cause

`catch return` was used as a terse "give up here" without an error value. The two `dupeZ` buffers *are* correctly freed by `defer` at `:4161`/`:4164` — the leak alleged in the audit report is false; the only defect is the silent success return.

## Fix

Use `try compat.dupeZ(...)` so `error.OutOfMemory` propagates to `loadConfigFile`, or log a diagnostic and `continue` consistently with the non-fatal user-option paths (`:3991-4045`) so one directive cannot truncate the file.

## Verification status

Found by source-level validation of the audit report against live source. `zig build test` passes; no test injects allocation failure into config loading.
