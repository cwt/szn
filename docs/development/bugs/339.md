# Bug 339 — 91 instances of `catch {}` silent error suppression violates Zig 0.16 rule #6

### 339. `catch {}` silent error suppression (91 instances)
**Files:** `src/server/server.zig`, `src/cmd/cmd.zig`, `src/main.zig`, `src/window.zig`, `src/server/dispatch.zig`, `src/server/render.zig`, `src/input.zig`, `src/layout.zig`, `src/socket_path.zig`
**Severity:** HIGH
**Status:** 🔓 OPEN

Zig 0.16 rule #6 mandates: *"No silent errors — `catch {}` is forbidden; use `try` or handle for real."* The codebase contains **91 instances** of `catch {}` that discard all errors without logging, propagating, or acting on them.

**Cluster locations:**

| File | Approx. count | Typical pattern |
|---|---|---|
| `src/server/server.zig` | ~60 | `pane.feedPty() catch {}`, `pane.writeInput(...) catch {}`, `self.setMessage(...) catch {}`, `pane.resizeTerminal(...) catch {}`, `self.executeAction(...) catch {}`, `self.handleMouseFocus(...) catch {}`, `self.addLogMessage(...) catch {}`, `self.command_buf.appendSlice(...) catch {}`, `self.last_search.appendSlice(...) catch {}` |
| `src/cmd/cmd.zig` | 4 | `session.windows.insert(arena_alloc, ...) catch {}`, `sp.resizeTerminal(...) catch {}`, `server.setMessage(msg) catch {}`, `session.options.set(...) catch {}` |
| `src/main.zig` | 2 | `display.enterAltScreen() catch {}`, `defer display.exitAltScreen() catch {}` |
| `src/server/dispatch.zig` | 1 | `server.addLogMessage(log_msg) catch {}` |
| `src/server/render.zig` | 1 | `lc.resize(alloc, expected_len) catch {}` |
| `src/window.zig` | 3 | `self.feedPty() catch {}`, `self.resize(self.width, self.height) catch {}` (×2) |
| `src/input.zig` | 1 | `self.dispatchOsc() catch {}` |
| `src/layout.zig` | 1 | `errdefer pane.resizeTerminal(old_w, old_h) catch {}` |
| `src/socket_path.zig` | 1 | `resolve(&buf) catch {}` |

**Why this matters:** Silent error suppression turns recoverable failures into silent state corruption. For example, `pane.feedPty() catch {}` means PTY read failures are invisible — the pane may stop receiving output with no log entry. `pane.writeInput(...) catch {}` means keypresses sent to a pane are silently dropped. `self.setMessage(msg) catch {}` means command responses can fail to deliver with no trace.

**The Zig 0.16 rule is unambiguous:** never write `catch {}` or `catch |_| {}`. Every instance should either:
1. `try` the call (propagate the error), or
2. `catch |err| std.log.warn("...: {any}", .{err})` (log and continue), or
3. `catch return err` (convert to early return).

**Fix priority:** This is a code-quality sweep — each `catch {}` must be reviewed individually to decide whether the operation is critical (use `try`) or best-effort (log on failure). The server loop in `server.zig` is the largest target with ~60 instances.
