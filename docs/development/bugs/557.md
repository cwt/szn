# Bug 557 — Config and option parsing/scoping bugs

### 557. `cfg.parseValue`/`options.coerceValue` type mismatch, quoting defects, missing `-u`/`setw -g` propagation, and synchronous `if-shell` deadlock
**Severity:** HIGH  
**Status:** ✅ RESOLVED  
**Files:** [`src/cfg.zig:162-197`](https://github.com/cwt/szn/blob/main/src/cfg.zig#L162-L197), [`src/cfg.zig:244-275`](https://github.com/cwt/szn/blob/main/src/cfg.zig#L244-L275), [`src/cfg.zig:412-424`](https://github.com/cwt/szn/blob/main/src/cfg.zig#L412-L424), [`src/options.zig:152-195`](https://github.com/cwt/szn/blob/main/src/options.zig#L152-L195), [`src/cmd/cmd.zig:959-1089`](https://github.com/cwt/szn/blob/main/src/cmd/cmd.zig#L959-L1089), [`src/server/server.zig:3647-3665`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L3647-L3665)

## Problem

1. **Bidirectional `cfg.parseValue` + `options.coerceValue` type mismatch (`src/cfg.zig:244-275`, `src/options.zig:152-195`, `src/cmd/cmd.zig:999`)**:
   - In `:set` / CLI (`setOptionInternal`), `cmd.parse` has already stripped outer quotes from `val_str`. `cfg.parseValue(val_str)` then classifies any 1-character string (`" "`, `"|"`, `"a"`) or key name (`"F1"`) as `.key`, any integer (`"123"`) as `.number`, `"on"`/`"off"` as `.flag`, and `"red"` as `.colour`. When `options.coerceValue` runs for a `.string` option (like `status-left`, `default-shell`, `word-separators`), it rejects `.key`, `.number`, `.flag`, and `.colour` with `error.TypeMismatch`!
   - Conversely, in `szn.conf`, if a user quotes a non-string option (e.g. `set -g prefix "C-a"`, `set -g mouse "on"`, `set -g history-limit "5000"`), `cfg.parseValue` returns `.string`, which `options.coerceValue` rejects for `.key`, `.flag`, and `.number` options with `error.TypeMismatch`.

2. **Quoting and escaping defects in `src/cfg.zig`**:
   - `findUnescapedQuote` (`src/cfg.zig:412-424`) checks `if (s[i] == q and (i == 0 or s[i - 1] != '\\'))`, which fails when an even number of backslashes precedes the closing quote (`"foo\\"`).
   - `cfg.parseValue` (`src/cfg.zig:250-253`) returns `raw[1 .. raw.len - 1]` for double-quoted strings without calling `unescapeQuoted`, leaving literal `\"` and `\\` in option values.
   - `stripInlineComment` (`src/cfg.zig:172`) checks `if (ch == '\\' and i + 1 < line.len)` unconditionally even when `in_single` (`'...'`) is true, so `'foo\'` treats the closing `'` as escaped.

3. **Incomplete flag support and `setw -g` propagation in `setOptionInternal` (`src/cmd/cmd.zig:959-1089`)**:
   - `setOptionInternal` does not support `-u` (unset) or combined flags (`-gu`, `-gw`, `-q`), even though `cfg.zig` supports `set -u` / `set -gu`.
   - `set-window-option -g` (`setw -g`) updates `server.global_window_options` and the single currently active window (`session.active_window`), but does not update `session.window_options` or any other open windows across sessions.

4. **Synchronous `c.system()` in `if-shell` can deadlock the server (`src/server/server.zig:3647-3665`)**:
   `Server.applyDirectives` executes `if-shell` synchronously via `const ret = c.system(cmd_z.ptr);`. Because the server is single-threaded, any `if-shell` command that runs an `szn` client command against the same server deadlocks permanently (or hangs the server if the shell command blocks).

## Proposed Fix

1. Parse option values directly against the target option's `OptionType` from `options.findOptionDef(opt_name)` (or allow `options.coerceValue` to coerce between `.string` and `.key`/`.flag`/`.number`/`.colour` using the raw token text).
2. Fix `findUnescapedQuote` and `stripInlineComment` to track backslash parity only outside single quotes, and unescape double-quoted strings.
3. Support `-u` and combined flags (`-gu`, `-gw`, `-q`) in `setOptionInternal`, and propagate `setw -g` across all sessions/windows (or through `Options.parent` inheritance).
4. Run `if-shell` asynchronously via `Loop` / `SIGCHLD` or set an environment/timeout guard so it cannot deadlock the server event loop.
