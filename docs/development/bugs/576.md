# Bug 576 — Alt + non-ASCII UTF-8 keys are mangled

### 576. `feedEsc` has no UTF-8 lead-byte branch, unlike `feedGround`

**Severity:** LOW  
**Status:** ⬜ OPEN  
**Files:** [`src/tty/tty_key.zig:61-96`](https://github.com/cwt/szn/blob/main/src/tty/tty_key.zig#L61-L96), [`:99-115`](https://github.com/cwt/szn/blob/main/src/tty/tty_key.zig#L99-L115), [`:177-197`](https://github.com/cwt/szn/blob/main/src/tty/tty_key.zig#L177-L197), [`src/server/server.zig:148`](https://github.com/cwt/szn/blob/main/src/server/server.zig#L148)  
**Related:** [Bug #183](./183.md) (double-ESC handling), [Bug #552](./552.md) (Escape flushing), [Bug Index](./index.md)

## Symptom

`feedGround` recognizes UTF-8 lead bytes (`0xC2..0xF4`) at `tty_key.zig:78-95` and enters `.utf8_2/.utf8_3/.utf8_4`. `feedEsc` does not:

```zig
// tty_key.zig:99-115
fn feedEsc(rd: *InputReader, byte: u8) ?Event {
    if (byte == '[') { ... }
    if (byte == 'O') { ... }
    if (byte == 0x1B) { ... return escape; }
    rd.state = .ground;
    return Event{ .key = .{ .char = .{ .code = byte, .mod = .{ .alt = true } } } };
}
```

Pressing `Alt+ท` sends `1B E0 B8 97`. The lead byte `0xE0` is emitted as `U+00E0` with `alt = true`, then `0xB8` and `0x97` are fed to `feedGround`, which has no continuation-byte branch and returns `null` (`:96`) — both bytes are discarded. The application receives `Alt+à` instead of `Alt+ท`[^src-1].

`InputReader` is production code: `Server.input_reader` is declared at `server.zig:148` and fed at `:1751` (and in modal paths), so this is not a test-only defect[^src-2].

## Cause

The escape-state parser was written for ASCII Alt combinations only. The UTF-8 decoder lives exclusively in `feedGround`, so a multibyte lead arriving immediately after ESC bypasses it.

## Fix

In `feedEsc`, if `std.unicode.utf8ByteSequenceLength(byte)` yields a length > 1, store `rd.buf[0] = byte`, set `rd.pos = 1`, switch to the corresponding `.utf8_N` state, and remember that the sequence is Alt-modified (e.g. a new `utf8_alt: bool` flag on `InputReader`) so `feedUtf8` can attach `.mod = .{ .alt = true }` when it completes. Reset that flag on completion and on interruption. Also guard `rd.pos = 0` before re-feeding an interrupted sequence.

## Verification status

Found by source-level validation of the audit report against live source. The report's `utf8_alt` field and interrupted-`rd.pos` claims were not present as described; only the `feedEsc` lead-byte defect is recorded here. `zig build test` passes; no test feeds `ESC` followed by a multibyte lead byte.
