# Bug 342 — `std.ArrayList.toOwnedSlice()` is removed in Zig 0.16

### 342. `toOwnedSlice` — removed in Zig 0.16
**Files:** `src/cfg.zig:385`, `src/cmd/cmd.zig:1576,1614,1630`, `src/format.zig:175,183,404,496`, `src/mode_copy.zig:394`, `src/status.zig:168,230`, `src/thai.zig:560`
**Severity:** HIGH
**Status:** 🔓 OPEN

Zig 0.16 removed `std.ArrayList(T).toOwnedSlice(allocator)`. The recommended replacement depends on the ownership model:

- If the caller already owns the allocator and expects an owned slice, return `try gpa.dupe(u8, list.items)` or use a scratch arena.
- If the list is local and the caller takes ownership of the buffer, return `list.toOwnedSlice()` was the old pattern; now you must manually transfer: `const owned = list.items; list.items.len = 0; list.capacity = 0; return owned;` (the caller must then free via the same allocator).
- Most common fix: instead of building a list then calling `toOwnedSlice`, use `std.io.fixedBufferStream` / `std.Io.Writer.fixed` or pre-allocate with known size via `allocator.alloc`.

**Fix approach per site:** Each call site must be reviewed individually. The typical pattern is to replace `try list.toOwnedSlice(allocator)` with either:
1. `const s = list.items; list.items.len = 0; return s;` (caller must free), or
2. Pre-allocate the buffer with `allocator.alloc(u8, estimated_len)` and write into it directly, or
3. Use `std.Io.Writer.fixed` with a known-size buffer when the output size is bounded.
