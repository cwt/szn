# Bug 361 — saved_grid churn leaks a grid per mode toggle

### 361. Copy-mode / clock-mode / choose-buffer cycles grow memory forever
**File:** `src/window.zig:66-79`; clone sites `src/server/server.zig:1100`,
`src/server/server.zig:1390`, `src/cmd/cmd.zig:553-574`
**Severity:** HIGH
**Status:** 🔴 OPEN

### Problem
`restoreSavedGrid` does `self.screen.grid.deinit()` before restoring — an arena
no-op. Overwrite-before-clone is correctly guarded everywhere (`if
(pane.saved_grid) |*g| { g.deinit(); ... }`), so ownership is never double-held;
the leak is pure arena bloat: one full grid (+ cloned history) retained forever
per toggle.

### Fix (proposed)
Same strategy as #359/#360: allocate saved grids from a resettable scratch
arena that is reset after restore, or stop cloning entirely by rendering
copy-mode from `(grid, scroll_offset)` state as tmux does.
