# Bug 503 — cellHasMaiHanAkat raw-codepoint check compares table index to raw codepoint

### 503. Competing conventions: raw codepoint branch is dead and risks false positives
**Severity:** LOW  
**Status:** 🟢 FIXED  
**Files:** [`src/thai.zig:96-105`](https://github.com/cwt/szn/blob/main/src/thai.zig#L96-L105), [`src/char_width.zig:198-219`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L198-L219)

## Problem

In [`src/thai.zig`](https://github.com/cwt/szn/blob/main/src/thai.zig), [`cellHasMaiHanAkat`](https://github.com/cwt/szn/blob/main/src/thai.zig#L96) checks whether a cell contains MAI HAN AKAT (`U+0E31`):

```zig
pub fn cellHasMaiHanAkat(cell: Cell) bool {
    if (cell.char == 0x0E31) return true;
    if (cell.comb1 != 0) {
        if (cell.comb1 == 0x0E31 or char_width.combiningCodepoint(cell.comb1) == 0x0E31) return true;
    }
    if (cell.comb2 != 0) {
        if (cell.comb2 == 0x0E31 or char_width.combiningCodepoint(cell.comb2) == 0x0E31) return true;
    }
    return false;
}
```

The fields `Cell.comb1` and `Cell.comb2` are defined as `u13` (13 bits, range `0..8191`). In the actual terminal parser and grid pipeline ([`src/screen.zig:808, 856`](https://github.com/cwt/szn/blob/main/src/screen.zig#L808)), combining codepoints are converted to 1-based table indices using [`char_width.combiningIndex(cp)`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L198):
```zig
prev_cell.comb1 = char_width.combiningIndex(cp);
```

All subsystems (rendering in [`src/server/render.zig`](https://github.com/cwt/szn/blob/main/src/server/render.zig), TTY output in [`src/tty/tty.zig`](https://github.com/cwt/szn/blob/main/src/tty/tty.zig), copy mode in [`src/mode_copy.zig`](https://github.com/cwt/szn/blob/main/src/mode_copy.zig), and libthai conversion in [`src/thai.zig:522`](https://github.com/cwt/szn/blob/main/src/thai.zig#L522)) resolve combining marks via [`char_width.combiningCodepoint(cell.comb1)`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L216).

Comparing `cell.comb1 == 0x0E31` directly:
1. Is completely dead in production because `comb1` holds an index (~300), not the raw codepoint (`0x0E31` = 3633).
2. Is conceptually hazardous: if the combining mark table ever grew to contain 3,633 entries, whatever unrelated mark mapped to index 3,633 would be falsely identified as MAI HAN AKAT.
3. Only existed due to a few ad-hoc unit test initializations in [`src/grid.zig`](https://github.com/cwt/szn/blob/main/src/grid.zig) that bypassed `combiningIndex`.

## Proposed Fix

1. In [`src/thai.zig`](https://github.com/cwt/szn/blob/main/src/thai.zig), simplify [`cellHasMaiHanAkat`](https://github.com/cwt/szn/blob/main/src/thai.zig#L96) to consistently check only via [`char_width.combiningCodepoint`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L216):
   ```zig
   pub fn cellHasMaiHanAkat(cell: Cell) bool {
       if (cell.char == 0x0E31) return true;
       if (cell.comb1 != 0 and char_width.combiningCodepoint(cell.comb1) == 0x0E31) return true;
       if (cell.comb2 != 0 and char_width.combiningCodepoint(cell.comb2) == 0x0E31) return true;
       return false;
   }
   ```
2. Ensure all tests store combining marks via `char_width.combiningIndex(cp)` instead of raw codepoint literals.

## Resolution

- In [`src/thai.zig`](https://github.com/cwt/szn/blob/main/src/thai.zig), simplified [`cellHasMaiHanAkat`](https://github.com/cwt/szn/blob/main/src/thai.zig#L96) to check only via [`char_width.combiningCodepoint`](https://github.com/cwt/szn/blob/main/src/char_width.zig#L216), eliminating the dead `comb1 == 0x0E31` comparison against table indices.
- Standardized test cases in [`src/thai.zig`](https://github.com/cwt/szn/blob/main/src/thai.zig) to store combining marks using `char_width.combiningIndex(...)`.
- Added missing blank `///` line in `isThaiFollowingVowel` docstring to avoid Markdown text collapse.
