## HIGH Severity

### H1: Use-after-free of MessageReader in handleClient packet loop

**File:** `src/server/server.zig:2434-2478`
**Confidence:** 95%
**False Positive Lessons:** None apply (GPA-allocated, not arena; ownership is explicit hash map)

**Root Cause:**
```zig
// Line 2434
const reader = self.client_readers.get(fd) orelse return;
try reader.feed(buf[0..n]);

while (try reader.tryParse()) |pkt| {
    defer reader.consume(pkt);
    // ... handler dispatch ...
    .detach => {
        self.removeClient(fd);  // Line 2554: destroys reader
        // ...
    },
}
// Loop exits → deferred reader.consume() operates on freed memory
```

`handleClient()` holds a raw pointer to `MessageReader` obtained from the hash map. Inside the packet-parse loop, any handler can call `removeClient(fd)` (e.g., detach), which executes:
```zig
if (self.client_readers.fetchRemove(fd)) |entry| {
    self.allocator.destroy(entry.value);  // Frees the reader
}
```
After the loop exits, the deferred `reader.consume(pkt)` dereferences the now-freed pointer.

**Trigger:** Remote client sends detach packet mid-batch. Attacker-controlled path, requires valid connection.

**Fix:** Capture reader by value or null out the pointer after `removeClient()` returns. Or restructure to not hold raw pointers across handler dispatch.

### H2: IRM insert mode decrements sixel refcounts for shifted cells, not just overwritten

**File:** `src/screen.zig:799-807`
**Confidence:** 90%
**False Positive Lessons:** #278/#279 already fixed insertLines/deleteLines; this is a different code path (character insert)

**Root Cause:**
```zig
if (self.mode.insert) {
    var x = self.grid.width - 1;
    while (x > self.cursor.x) : (x -= 1) {
        // bug #225: decrement refcount for the overwritten cell.
        self.decrementMainGridRef(x, self.cursor.y);  // WRONG: cell is shifted, not destroyed
        const prev = self.grid.getCell(x - 1, self.cursor.y);
        self.grid.setCell(x, self.cursor.y, prev);
    }
}
// bug #225: decrement refcount before overwriting.
self.decrementMainGridRef(self.cursor.x, self.cursor.y);  // CORRECT: this cell IS overwritten
```

When insert mode is active, characters shift right. The loop decrements refcounts for every destination cell, but those cells are being COPIED TO, not DESTROYED. Only the cell at `cursor.x` is actually overwritten with new content and needs refcount decrement.

**Effect:** Sixel images in the insert range get their refcounts prematurely zeroed. Images disappear or slot reuse causes corruption.

**Fix:** Remove the decrement from inside the shift loop. Only decrement for the cell at `cursor.x`.

### H3: DECSTBM top > bottom causes u32 underflow and line buffer aliasing

**File:** `src/screen.zig:1257-1262`
**Confidence:** 95%
**False Positive Lessons:** None (numeric proof: `@min(bottom, height-|1)` where bottom=0, height=1 gives 0, but top could be larger)

**Root Cause:**
```zig
pub fn setScrollRegion(self: *Screen, top: u32, bottom: u32) void {
    self.scroll_region = .{ @min(top, self.grid.height -| 1), @min(bottom, self.grid.height -| 1) };
    self.cursor.x = 0;
    self.cursor.y = if (self.mode.origin) self.scroll_region.?[0] else 0;
    self.dirty = true;
}
```

If `top > bottom` (invalid per spec but acceptably received from terminal), both values are clamped independently. The resulting region has `top >= bottom`. Downstream code assumes `top < bottom` and uses these as array indices without validation:
- `grid.getLineMut(top)` and `grid.getLineMut(bottom)` may alias same line
- Scroll operations compute `bottom + 1 - y` which can underflow if `y > bottom`

**Trigger:** Any program sending `ESC [N;M r` with N > M (e.g., `ESC [5;3 r`).

**Fix:** Validate `top < bottom` after clamping; reject invalid regions by clearing scroll region.

### H4: `#{=N:var}` truncation panics on mid-UTF-8 codepoint boundary

**File:** `src/format.zig:737-747`
**Confidence:** 85%
**False Positive Lessons:** Not arena-related; panic path is real

**Root Cause:**
```zig
var idx: usize = 0;
while (idx < value.len) {
    const len = std.unicode.utf8ByteSequenceLength(value[idx]) catch 1;
    if (count >= n) break;
    count += 1;
    idx += len;
}
// idx now points MID-UTF-8 sequence if truncated
if (!negative) {
    try out.appendSlice(allocator, value[0..idx]);  // PANIC: invalid UTF-8 slice
}
```

When truncating to N codepoints, `idx` may land in the middle of a multi-byte UTF-8 sequence. The slice `value[0..idx]` then contains a malformed UTF-8 prefix, which `appendSlice` may reject or produce invalid output.

**Trigger:** Pane title from OSC 0/2 contains multi-byte UTF-8; status line template requests `#{=5:title}` where 5th codepoint is multi-byte.

**Fix:** Back up `idx` to previous codepoint boundary before slicing.

### H5: DCS `$ q` (DECRQSS) misrouted to sixel parser

**File:** `src/input.zig:462-467`
**Confidence:** 80%
**False Positive Lessons:** #298 was instrumentation, not fix; this is the underlying bug

**Root Cause:**
```zig
fn advanceDcsIntermediate(self: *InputParser, byte: u8) Error!void {
    switch (byte) {
        0x20...0x2F => {},
        'q' => {
            self.dcs_is_sixel = true;  // ANY DCS ending in 'q' treated as sixel
            self.dcs_buf.clearRetainingCapacity();
            try self.dcs_buf.appendSlice(self.screen.allocator, "\x1bPq");
            self.state = .dcs_sixel;
        },
```

DCS sequences ending in `q` include both sixel (`ESC P q`) and DECRQSS (`ESC P $ q`). The parser only checks the final intermediate byte (`q`), not the preceding delimiter (`$`). DECRQSS requests from terminals or opencode get treated as sixel streams and dispatched to `dispatchDcsSixel()`.

**Trigger:** Any terminal or tool sending DCS `$ q` (common in query sequences).

**Fix:** Check for `$` delimiter in the DCS body before setting `dcs_is_sixel`.

### H6: Kitty u-encoded keys never normalized to Special/Arrow/Function

**File:** `src/key.zig:143-176`
**Confidence:** 90%
**False Positive Lessons:** Not dead code; bindings exist and expect `.special` variants

**Root Cause:**
```zig
'u' => {
    // ... parse codepoint ...
    return Key{ .char = .{ .code = @intCast(codepoint), .mod = k_mod } };
},
```

kitty keyboard protocol's `u` final byte emits codepoints for ALL keys, including special keys like Tab (0x09), Enter (0x0D), Escape (0x1B), BS (0x08). The parser returns these as `.char` keys, but tmux/szn key bindings expect `.special` variants:
- `Tab` → should be `Key{ .special = .{ .key = .tab } }`
- `Enter` → should be `Key{ .special = .{ .key = .enter } }`
- `Escape` → should be `Key{ .special = .{ .key = .escape } }`

**Trigger:** kitty terminal with `kitty.reflow` disabled (uses u-protocol); user presses Tab/Enter/BS.

**Fix:** After parsing codepoint, check against special key values and normalize to `.special` enum before returning.

## MEDIUM-HIGH Severity

### M1: Render path bypasses appendClientOut for some output

**File:** `src/server/server.zig:3146-3153`
**Confidence:** 75%
**False Positive Lessons:** #298 flow control is about backpressure, not this path

**Root Cause:**
```zig
dc.out_buf.appendSlice(self.allocator, hdr[0..]) catch {
    append_ok = false;
};
if (append_ok) {
    dc.out_buf.appendSlice(self.allocator, self.render_buf.items) catch {
        dc.out_buf.shrinkRetainingCapacity(prev_len);
        append_ok = false;
    };
}
```

Render output is appended directly to `dc.out_buf` without going through `appendClientOut()`, which contains the deduplication logic and `RENDER_HIGH_WATERMARK` checks. This means:
- Flow-control watermark never triggers for render output
- Diagnostic counters in `appendClientOut` remain zero
- Duplicate frames can pile up in out_buf

**Effect:** Slow clients can accumulate unbounded render output; flow control broken for display path.

**Fix:** Route render output through `appendClientOut()` or replicate its watermark logic.

### M2: Mouse hit-testing uses codepoint count not cell width

**File:** `src/status.zig:108-123`
**Confidence:** 85%
**False Positive Lessons:** Not cosmetic — affects mouse interaction correctness

**Root Cause:**
```zig
pub fn visibleLen(s: []const u8) usize {
    var cols: usize = 0;
    var i: usize = 0;
    while (i < s.len) {
        if (s[i] == 0x1b) {
            i = skipEscape(s, i);
            continue;
        }
        const cp_len = std.unicode.utf8ByteSequenceLength(s[i]) catch 1;
        cols += 1;  // Always +1, ignores wide chars
        i += cp_len;
    }
    return cols;
}
```

`visibleLen()` counts codepoints, not cell columns. Wide characters (CJK, emoji, etc.) occupy 2 cells but count as 1. Mouse hit-testing in status bar uses this function to map mouse column to status piece.

**Effect:** Clicking on status bar with wide-char window names lands on wrong pane/section.

**Fix:** Use `char_width.zig` width lookup instead of codepoint counting.

### M3: Pane-border-format cache staleness on resize

**File:** `src/server/server.zig` (render path)
**Confidence:** 70%
**False Positive Lessons:** Cache invalidation is complex; not a simple missing clear

**Root Cause:** Pane-border format strings are cached per-pane-per-client. When pane dimensions change (resize, split, rotate), the cached format string may contain stale width-dependent expansions (e.g., `#{width}`, `#{height}`). Cache invalidation doesn't trigger on all dimension changes.

**Effect:** Stale border rendering after resize operations.
